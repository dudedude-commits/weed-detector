# Сорняки на фотографиях с дрона — Задание 1

Решение находит на фото полей с дрона сорняки, определяет их вид и
стадию вегетации, считает количество и сохраняет результат в JSON/CSV
вместе с фото, на которых объекты обведены кружками (цвет кружка = вид,
расшифровка цветов — прямо на фото, в подписи-легенде).

## Как это устроено

1. **Сегментация** (`pipeline/segmentation.py`) — по индексу Excess Green
   (`2G-R-B`) и адаптивной бинаризации Otsu на фото поля выделяется вся
   растительность, затем она разбивается на отдельные кустики (связные
   компоненты) — это кандидаты в сорняки.
2. **Признаки** (`pipeline/features.py`) — для каждого кандидата и для
   каждого эталонного фото считается один и тот же вектор признаков:
   цветовая гистограмма (HSV), текстура листа (LBP) и форма контура
   (инвариантные моменты Ху, вытянутость, выпуклость).
3. **Классификация** (`pipeline/classifier.py`) — вид и стадия
   определяются методом k ближайших соседей (k-NN, косинусное
   расстояние) относительно загруженных эталонных фото. Это **few-shot**
   подход: не нужно обучать нейросеть — достаточно 10–30 эталонных фото
   на класс, база пополняется через интерфейс.
4. **Оркестрация и вывод** (`pipeline/pipeline.py`) — отбор по порогу
   уверенности, подсчёт по видам/стадиям, отрисовка рамок, сохранение
   `results.json` / `detections.csv` / `summary.csv`.

Такой подход выбран сознательно: организаторы не дали разметку
(bounding box) на фото полей — только эталонные фото по видам/стадиям,
как в папке `Dataset/Сорняки`. Обучить детектор с нуля на 5 демо-фото
невозможно, поэтому используется классическое компьютерное зрение +
сравнение с эталонами, которое работает сразу, без обучения, и
переносится на любое число новых видов/фото через загрузку эталонов.

## Быстрый старт (рекомендуется)

Один стартовый файл сам создаст виртуальное окружение, поставит зависимости
и откроет веб-интерфейс на `http://localhost:8501`:

- **Linux / macOS:**
  ```bash
  ./start.sh
  ```
- **Windows:** двойной клик по `start.bat` (или запустить в консоли).

## Установка вручную

```bash
python3 -m venv venv && source venv/bin/activate   # опционально
pip install -r requirements.txt
```

## Запуск веб-интерфейса (с загрузкой фото прямо в браузере)

```bash
streamlit run app.py
```

Откроется страница, где можно:

1. **Загрузить эталонные фото сорняков** — выбрать/вписать вид, указать
   стадию вегетации (розетка / стеблевание / «без стадии» — для злаков
   вроде пырея, у которых розетки не бывает) и загрузить несколько фото.
   Эталоны сохраняются на диск в `reference_data/<Вид>/<Стадия>/` — при
   следующем запуске база никуда не денется.
2. **Загрузить фото полей с дрона** — один или сразу несколько снимков.
3. Нажать **«Запустить анализ»** — сразу под сводкой появятся кнопки
   скачивания `results.json`, `detections.csv` и общего `.zip`, а ниже —
   фото полей с найденными сорняками (каждый обведён кружком своего
   цвета, расшифровка цветов дана в подписи в углу фото), таблица
   находок и отдельные "отсечённые" вырезки каждого сорняка (фон
   прозрачный) со своими кнопками скачивания PNG.

## Запуск без интерфейса (пакетная обработка / CLI)

Если эталоны уже лежат на диске в нужной структуре (например,
`reference_data/Бодяк полевой/Розетка/*.jpg`), можно обработать папку с
фото полей одной командой:

```bash
python main.py --ref-dir reference_data --field-dir uploads/fields --out-dir results
```

Результат появится в `results/`:

- `results.json` — по каждому фото: список найденных объектов
  (bbox, вид, стадия, уверенность, путь к вырезке `crop_file`) и сводные счётчики;
- `detections.csv` — та же информация построчно (включая колонку `crop_file`);
- `summary.csv` — количество экземпляров по виду/стадии на каждом фото;
- `annotated/` — фото полей: каждый найденный объект обведён кружком
  своего цвета (цвет = вид), в углу фото — подпись-легенда "цвет → вид";
- `crops/` — отдельная "отсечённая" вырезка каждого найденного сорняка:
  PNG с прозрачным фоном везде, где не растение (файл `<фото>_<id>.png`,
  тот же путь записан в `crop_file` в JSON/CSV — так каждую строку таблицы
  можно открыть как отдельную картинку).

## Формат `results.json`

```json
[
  {
    "image": "DJI_20260615134520_0343_D.JPG",
    "width": 4000,
    "height": 3000,
    "detections": [
      {
        "id": 1,
        "bbox": [812, 430, 210, 180],
        "species": "Бодяк полевой",
        "stage": "Розетка",
        "confidence": 0.78,
        "area_px": 24310,
        "crop_file": "crops/DJI_20260615134520_0343_D_001.png"
      }
    ],
    "counts": { "Бодяк полевой (Розетка)": 1 }
  }
]
```

## Структура проекта

```
weed_detector/
├── start.sh                # стартовый файл Linux/macOS (venv + зависимости + запуск)
├── start.bat                # стартовый файл Windows
├── app.py                 # Streamlit-интерфейс (загрузка + результаты)
├── main.py                 # CLI-запуск без браузера
├── requirements.txt
├── .streamlit/config.toml  # тема интерфейса (цвета, шрифт)
├── reference_data/         # база эталонов (вид/стадия/фото), пополняется через UI
├── uploads/fields/          # (опционально) фото полей для CLI-режима
├── results/                 # результаты CLI-запуска
│   ├── annotated/           # фото полей с кружками по видам и легендой цветов
│   └── crops/               # отсечённые вырезки каждого найденного сорняка (PNG, прозрачный фон)
└── pipeline/
    ├── segmentation.py     # выделение растительности и отдельных кустов
    ├── features.py          # цвет + текстура + форма -> вектор признаков
    ├── classifier.py        # база эталонов + k-NN классификация
    └── pipeline.py           # оркестрация, отрисовка, экспорт JSON/CSV
```

## Если start.bat не запускается (Windows)

**Окно мелькает и сразу закрывается** — оно закрывается до того, как вы
успеваете увидеть ошибку. Чтобы увидеть, что именно пошло не так:

1. Нажмите `Win + R`, введите `cmd`, нажмите Enter — откроется окно консоли.
2. Перетащите в него файл `start.bat` (или папку `weed_detector`, затем
   допишите `\start.bat`) и нажмите Enter.
3. Теперь окно не закроется само — вы увидите текст ошибки.

**Ошибка при установке зависимостей** вида `ERROR: Could not find a version
that satisfies the requirement numpy>=1.24` / `No matching distribution
found for numpy` — значит на компьютере используется старый Python
(младше 3.9, часто это Python 3.7, который мог остаться от другой
программы). `start.bat` начиная с этой версии сам ищет через `py`-launcher
более новую версию Python, даже если `python` на PATH указывает на старую —
но если на компьютере вообще нет Python 3.9+, ни установленного, ни
доступного через `py`, скрипт покажет соответствующее сообщение.

Решение: установите Python 3.10-3.12 (не самую новую 3.13+, чтобы избежать
проблем совместимости других библиотек) с
[python.org/downloads](https://www.python.org/downloads/) — при установке
обязательно отметьте галочку **«Add python.exe to PATH»**. Затем удалите
папку `.venv` (если она уже была создана со старым Python) и запустите
`start.bat` заново.

## Известные ограничения и что можно улучшить дальше

- Точность классификации напрямую зависит от числа и разнообразия
  эталонных фото — рекомендуется 20+ фото на вид/стадию, снятых в
  похожих условиях освещённости, что и целевые фото полей.
- Сегментация по цвету может путать сорняк и культуру, если они совпадают
  по оттенку зелёного — для более сложных случаев эту функцию
  (`find_plant_blobs`) можно заменить на предобученную сегментационную
  модель (например, SAM) или дообучить лёгкий детектор, когда появится
  размеченный датасет с bounding box.
- Стадии вегетации сравниваются только внутри уже определённого вида;
  для видов без папки «стадия» (как пырей в исходном датасете) стадия
  не предсказывается — это ожидаемое поведение, а не ошибка.
